Glossary & references

Definitions of the terms used throughout this guide, plus the sources it draws on.

Glossary

TermMeaning
APIMAzure API Management, the gateway in front of every Nimbus feature.
Burn rateHow fast error budget is being used compared with spending it evenly. 1× uses the whole budget exactly over the SLO window.
CFTCross-functional team. Owns one or more feature experiences end to end.
cloud_RoleNameThe App Insights field holding the service name, mapped from OTel service.name.
Error budget1 − SLO: the amount of unreliability you're allowed over the window.
Feature experienceA user-facing Nimbus capability, such as Writing Assist or Device Care.
FoundryAzure AI Foundry, the platform hosting Nimbus's model deployments.
GenAI semantic conventionsOpenTelemetry's standard attribute names for generative AI calls, such as gen_ai.request.model and gen_ai.usage.input_tokens.
Golden signalsLatency, traffic, errors, and saturation.
ICIncident Commander. Coordinates the response and doesn't debug.
itemCountThe number of real events a sampled App Insights row stands for.
Noisy neighborOne workload using up shared capacity and hurting others.
operation_IdThe App Insights field holding the trace ID, which links all telemetry for one request.
PTUProvisioned Throughput Units: reserved model capacity with predictable latency, up to its limit.
SLI / SLOService level indicator (a measure of user experience) and objective (the target for it).
SpilloverSending requests that exceed PTU capacity to a pay-as-you-go deployment.
Tail-based samplingDeciding whether to keep a trace after it completes, so errors and slow traces can always be kept.
ToilManual, repetitive, automatable operational work with no lasting value.
TPMTokens per minute, the unit of Foundry quota.
traceparentThe W3C HTTP header that carries trace context between services.
TTFTTime to first token: delay before a streamed response starts.

Google SRE books

Both books are free to read online at sre.google. This guide summarizes their ideas in its own words.

Site Reliability Engineering (2016)

  • Embracing Risk: why 100% is the wrong target, and error budgets.
  • Service Level Objectives: SLIs, SLOs, and SLAs.
  • Eliminating Toil
  • Monitoring Distributed Systems: the four golden signals.
  • Effective Troubleshooting: forming and testing hypotheses.
  • Managing Incidents: incident command roles.
  • Postmortem Culture: Learning from Failure
  • Handling Overload and Addressing Cascading Failures: retries, load shedding.

The Site Reliability Workbook (2018)

  • Implementing SLOs
  • Alerting on SLOs: multi-window, multi-burn-rate alerts.
  • Example Error Budget Policy
  • Incident Response
