Toolkit

KQL query library

Copy-ready queries for Application Insights. Most Nimbus services have no dashboard, so these are your dashboards. Every query also works as a Grafana panel.

  • Run these in Application Insights → Logs. Change the time window and the role or feature variables first.
  • Always compare with a baseline (yesterday, last week). A number on its own tells you nothing.
  • Count with sum(itemCount), not count(), because some services sample.
For senior managers · you don't need to run these

Your role

  • Ask for the chart, not the query. Engineers can share a link in the incident channel.
  • Notice when the team is writing queries from scratch during every incident. That's toil, and it's a sign dashboards are missing.

Questions to ask

  • Compared to what? Is this number unusual for this time of day?
  • Can you post that chart in the channel so everyone sees the same thing?
  • Which of these queries should become a permanent dashboard?

Conventions used below

PatternWhy
coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName)Not every CFT sets feature.experience, so fall back to the service name.
target has_any ("openai.azure.com", "services.ai.azure.com")Picks out Foundry model calls among all dependencies.
extract(@"deployments/([^/]+)/", 1, data)Gets the deployment name from the request URL when gen_ai.request.model is missing.
sum(itemCount)Corrects for sampling. A sampled row with itemCount = 10 stands for 10 real requests.
Using these in Grafana

In a Grafana panel with the Azure Monitor data source, choose Logs, paste the query, and replace timestamp > ago(1h) with $__timeFilter(timestamp) so the panel follows the dashboard's time picker. Use bin(timestamp, $__interval) for time series.

Latency

KQLLatency by feature experience, now vs yesterdayWhich feature got slower, and by how much?
let window = 1h;
requests
| where timestamp > ago(window) or timestamp between (ago(1d + window) .. ago(1d))
| extend period = iff(timestamp > ago(window), "cur", "base")
| extend feature = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName)
| summarize p95_ms = percentile(duration, 95) by feature, period
| evaluate pivot(period, any(p95_ms))
| extend ratio = round(todouble(cur) / todouble(base), 2)
| order by ratio desc
KQLP50 / P95 / P99 over time for one featureWhen did it start? Is it getting better or worse?
let role = "writing-assist-svc";   // cloud_RoleName of the service
requests
| where timestamp > ago(6h) and cloud_RoleName == role
| summarize p50 = percentile(duration, 50), p95 = percentile(duration, 95), p99 = percentile(duration, 99)
    by bin(timestamp, 5m)
| render timechart
KQLDependency breakdown for one featureIs time going to the model, retrieval, Graph, or our own code?
let role = "writing-assist-svc";
let window = 1h;
requests
| where timestamp > ago(window) and cloud_RoleName == role
| project operation_Id, request_ms = duration
| join kind=leftouter (
    dependencies
    | where timestamp > ago(window) and cloud_RoleName == role
    | extend hop = case(
        target has_any ("openai.azure.com", "services.ai.azure.com"), "model",
        target has "search.windows.net", "retrieval",
        target has "graph.microsoft.com", "graph",
        "other")
    | summarize hop_ms = sum(duration) by operation_Id, hop
  ) on operation_Id
| summarize p50_hop_ms = percentile(hop_ms, 50), p95_hop_ms = percentile(hop_ms, 95),
            p95_request_ms = percentile(request_ms, 95) by hop
| order by p95_hop_ms desc
Parallel calls overlap

If a service calls retrieval and the model in parallel, the hop times add up to more than the request time. If p95_request_ms is much larger than every hop, the time is going to the service's own code or to dependencies that aren't instrumented.

KQLTime to first token vs total model durationIs it queueing (TTFT up) or longer outputs (total up, TTFT flat)?
// nimbus.ttft_ms is emitted by Writing Assist only (see Environment → conventions)
dependencies
| where timestamp > ago(6h)
| where isnotempty(customDimensions["nimbus.ttft_ms"])
| extend ttft_ms = todouble(customDimensions["nimbus.ttft_ms"])
| summarize ttft_p50 = percentile(ttft_ms, 50), ttft_p95 = percentile(ttft_ms, 95),
            total_p95 = percentile(duration, 95) by bin(timestamp, 5m)
| render timechart

Errors

KQLError rate by feature and result codeWhich feature is failing, and with what?
requests
| where timestamp > ago(1h)
| extend feature = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName)
| summarize total = sum(itemCount), failed = sumif(itemCount, success == false) by feature
| extend error_pct = round(100.0 * failed / total, 2)
| join kind=leftouter (
    requests
    | where timestamp > ago(1h) and success == false
    | extend feature = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName)
    | summarize n = sum(itemCount) by feature, resultCode
    | summarize codes = make_bag(bag_pack(resultCode, n)) by feature
  ) on feature
| project feature, total, failed, error_pct, codes
| order by error_pct desc
KQLTop exceptionsWhat is our code actually throwing?
exceptions
| where timestamp > ago(1h)
| summarize occurrences = sum(itemCount), sample_message = any(outerMessage),
            first_seen = min(timestamp) by cloud_RoleName, type, problemId
| top 15 by occurrences
KQLContent-filter blocks by featureAre safety filters suddenly blocking more?
dependencies
| where timestamp > ago(24h)
| where target has_any ("openai.azure.com", "services.ai.azure.com")
| extend feature = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName),
         finish = tostring(customDimensions["gen_ai.response.finish_reasons"])
| summarize calls = sum(itemCount),
            output_filtered = sumif(itemCount, finish has "content_filter"),
            http_400 = sumif(itemCount, resultCode == "400")   // includes prompt blocks AND bad requests
    by feature, bin(timestamp, 15m)
| render timechart

Foundry, quota, and tokens

KQLModel latency and failures by deploymentIs one deployment or region slow, or all of them?
dependencies
| where timestamp > ago(1h)
| where target has_any ("openai.azure.com", "services.ai.azure.com")
| extend deployment = coalesce(tostring(customDimensions["gen_ai.request.model"]),
                               extract(@"deployments/([^/]+)/", 1, data))
| summarize calls = sum(itemCount), p50_ms = percentile(duration, 50), p95_ms = percentile(duration, 95),
            failed = sumif(itemCount, success == false) by deployment, target
| extend fail_pct = round(100.0 * failed / calls, 2)
| order by p95_ms desc
KQL429 throttling by deployment and callerWho is getting throttled, and on which deployment?
dependencies
| where timestamp > ago(1h)
| where target has_any ("openai.azure.com", "services.ai.azure.com")
| extend deployment = coalesce(tostring(customDimensions["gen_ai.request.model"]),
                               extract(@"deployments/([^/]+)/", 1, data)),
         caller = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName)
| summarize calls = sum(itemCount), throttled = sumif(itemCount, resultCode == "429") by deployment, caller
| extend throttle_pct = round(100.0 * throttled / calls, 2)
| order by throttled desc
KQLToken consumption per minute by callerWho is using up the shared quota (the noisy neighbor)?
dependencies
| where timestamp > ago(3h)
| where target has_any ("openai.azure.com", "services.ai.azure.com")
| extend deployment = coalesce(tostring(customDimensions["gen_ai.request.model"]),
                               extract(@"deployments/([^/]+)/", 1, data)),
         caller = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName),
         tokens = toint(customDimensions["gen_ai.usage.input_tokens"]) + toint(customDimensions["gen_ai.usage.output_tokens"])
| where deployment == "chat-small"
| summarize tokens_per_min = sum(tokens * itemCount) by caller, bin(timestamp, 1m)
| render areachart kind=stacked
KQLPrompt and completion size over 7 daysDid prompts quietly grow (more context, bigger retrieval chunks)?
dependencies
| where timestamp > ago(7d)
| where isnotempty(customDimensions["gen_ai.usage.input_tokens"])
| extend feature = coalesce(tostring(customDimensions["feature.experience"]), cloud_RoleName),
         in_tok = toint(customDimensions["gen_ai.usage.input_tokens"]),
         out_tok = toint(customDimensions["gen_ai.usage.output_tokens"])
| summarize p95_input = percentile(in_tok, 95), p95_output = percentile(out_tok, 95) by feature, bin(timestamp, 1h)
| render timechart
KQLModel calls per operation (retry detector)Are we retrying hard enough to amplify the problem?
dependencies
| where timestamp > ago(3h)
| where target has_any ("openai.azure.com", "services.ai.azure.com")
| summarize attempts = count(), throttled = countif(resultCode == "429")
    by operation_Id, cloud_RoleName, bin(timestamp, 5m)
| summarize avg_calls_per_op = avg(attempts), p99_calls_per_op = percentile(attempts, 99),
            ops_with_429 = countif(throttled > 0) by cloud_RoleName, timestamp
| render timechart

Device Care legitimately makes several model calls per operation because of its multi-step tool use, so compare against that service's own baseline. What matters is a jump in calls per operation.

Tracing

KQLFind the slowest operationsGive me some operation_Ids to inspect.
requests
| where timestamp > ago(1h) and cloud_RoleName == "writing-assist-svc"
| top 20 by duration desc
| project timestamp, operation_Id, name, duration, resultCode,
          client_version = tostring(customDimensions["client.version"])
KQLWalk one trace end to endWhat happened, in order, for this request?
let op = "PASTE_OPERATION_ID";
union requests, dependencies, exceptions, traces
| where timestamp > ago(1d) and operation_Id == op
| project timestamp, itemType, cloud_RoleName, name, target, duration, resultCode, success,
          detail = coalesce(message, outerMessage)
| order by timestamp asc
Visual alternative

In App Insights, open Transaction search, paste the operation ID, and open the end-to-end transaction details view for a Gantt chart of every span.

KQLErrors and latency by service version over timeDid it start when a new version went out?

requests

KQLWhen did each service version first appear?A deploy timeline even when nobody announced the deploy.
requests
| where timestamp > ago(7d)
| summarize first_seen = min(timestamp), last_seen = max(timestamp), requests = sum(itemCount)
    by cloud_RoleName, application_Version
| order by first_seen desc
KQLErrors and latency by desktop client versionIs a new desktop build the problem?
requests
| where timestamp > ago(6h)
| extend client = tostring(customDimensions["client.version"])
| where isnotempty(client)
| summarize total = sum(itemCount), failed = sumif(itemCount, success == false),
            p95_ms = percentile(duration, 95) by client
| extend error_pct = round(100.0 * failed / total, 2)
| order by total desc

Telemetry health

KQLTelemetry volume by typeDid data stop arriving? (Dashboards look "green" when there's no data.)
union requests, dependencies, traces, exceptions, customEvents
| where timestamp > ago(2d)
| summarize items = sum(itemCount) by itemType, bin(timestamp, 15m)

KQLService inventory and attribute coverageWhich services report, and which set our conventions?
requests
| where timestamp > ago(1d)
| summarize requests = sum(itemCount),
            has_feature = round(100.0 * countif(isnotempty(customDimensions["feature.experience"])) / count(), 0),
            has_owner = round(100.0 * countif(isnotempty(customDimensions["cft.owner"])) / count(), 0),
            sampled = max(itemCount) > 1
    by cloud_RoleName
| order by requests desc

SLOs

KQLMulti-window burn rate for one serviceAre we burning error budget fast enough to page?
let slo = 0.995;
let role = "writing-assist-svc";
let err_rate = (w: timespan) {
    requests
    | where timestamp > ago(w) and cloud_RoleName == role
    | summarize bad = sumif(itemCount, success == false), total = sum(itemCount)
    | project rate = todouble(bad) / todouble(total)
};
let b1h  = toscalar(err_rate(1h))  / (1 - slo);
let b5m  = toscalar(err_rate(5m))  / (1 - slo);
let b6h  = toscalar(err_rate(6h))  / (1 - slo);
let b30m = toscalar(err_rate(30m)) / (1 - slo);
print burn_1h = round(b1h, 1), burn_5m = round(b5m, 1), burn_6h = round(b6h, 1), burn_30m = round(b30m, 1)
| extend page_fast = burn_1h > 14.4 and burn_5m > 14.4,
         page_slow = burn_6h > 6 and burn_30m > 6

See Fundamentals → burn-rate alerts for where the thresholds come from. To turn this into an alert, use it as an Azure Monitor log search alert that fires when page_fast or page_slow is true.
