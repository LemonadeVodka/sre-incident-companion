Linear Operating Model

The daily only works if the board tells the truth. That takes a few shared rules: what each state means, what "ready" and "done" mean, how work is labeled, and which views you check. Agree them with the team once, write them down, and revisit them each quarter.

  • Every state has an entry rule and an exit rule.
  • Label every issue by work type, so you can see how much time goes to toil, interrupts, and projects.
  • Split anything bigger than three days.
  • Save five manager views and check them before the daily.

Blocked is best as a label or a blocking relation in Linear rather than a state, so the item keeps its place on the board and the blocker stays visible.

Definition of Ready and Done

Ready
  • Owner named
  • Problem and acceptance criteria written
  • Estimated, and 3 days or less (or split)
  • Linked to a project, SLO, incident, or request
  • Dependencies identified
Done
  • Merged and deployed, or the change is applied
  • Verified in production (a dashboard or query)
  • Runbook, dashboard, or alert updated if affected
  • NOC or the requesting team told, if relevant
  • Follow-ups filed as new issues

If Everything Is Urgent

If more than about 10% of open issues are Urgent or High, the priorities have stopped meaning anything. Re-rank them with the team in cycle planning.

Cycles, Projects, and Updates

  • Cycles (for example, two weeks) hold the planned work. Unfinished issues roll over, so watch the carryover.
  • Projects group issues toward an outcome, with a lead and a target date.
  • Project updates (On track / At risk / Off track) are posted weekly by the project lead. They feed your weekly note (template).
  • The Triage inbox is reviewed daily by a rotating person, so requests from the NOC and CFTs get an answer within a day.

Five Views to Save

  1. Aging WorkIn Progress for more than 3 days. Check before every daily.
  2. BlockedEverything with a blocked label or blocking relation, sorted by age.
  3. Not ReadyTodo items with no estimate, no owner, or no project.
  4. Incident Actionstype:incident-action by due date, so overdue ones are visible.
  5. WIP by PersonIn Progress grouped by assignee. Look for anyone with more than 2.

Linear and Locked-Down Jira

Some CFTs track work in Jira projects your team can't edit. Don't fight it. For each cross-team dependency, create one Linear issue that holds your side, link the Jira key in it, and add the blocked label until it moves. Your board then shows every dependency, even when another team's tool doesn't. See Risks & Dependencies.
