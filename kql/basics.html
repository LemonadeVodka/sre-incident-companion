Module 1: Basics

Four lessons that cover most of what you'll ever type: pick a table, filter it, choose columns, and count. Run each exercise in the demo workspace before you open the answer.

  • A query starts with a table, and each | passes rows to the next step.
  • where keeps rows. project keeps columns. extend adds columns. summarize counts and groups.
  • Always limit time first, with where timestamp > ago(1h).
  • Count with sum(itemCount), not count(), on Application Insights tables (sampling).

Lesson 1: Tables and Pipes

Concept. Telemetry lives in tables. Each row is one event, such as one request. The most useful tables for us are requests (calls into our services), dependencies (calls our services make to others: the model, partners, search), and exceptions (errors in our code). The pipe | means "then".

KQL · LessonLook at a Few RowsAlways start by looking at the data
requests
| take 10

take 10 shows any 10 rows. Use it to see which columns exist before writing a real query.

Service name: AppRoleName. Duration: DurationMs (milliseconds). In our classic tables these are cloud_RoleName and duration.

Lesson 2: Filtering and Time

Concept. where keeps only the rows that match. Always filter on time first. It makes queries fast and keeps you looking at the right moment. ago(1h) means "one hour before now". Other units: m (minutes), d (days).

KQL · LessonFailed Requests for One Service, Last HourFiltering by time, by service, and by outcome
requests
| where timestamp > ago(1h)
| where cloud_RoleName == "writing-assist-svc"
| where success == false
| take 20
You writeIt means
== / !=Equals / not equals (case-sensitive for text)
=~Equals, ignoring upper or lower case
has "zoom"Contains the whole word "zoom". Fast, and the usual choice.
contains "zo"Contains the letters anywhere. Slower.
in ("401", "403")Equals any value in the list
and / orCombine conditions
Exercise 2. In AppRequests, show 20 failed requests from the last 30 minutes.
Hint

The demo uses TimeGenerated and Success. Thirty minutes is 30m.

Answer
KQL · AnswerExercise 2
AppRequests
| where TimeGenerated > ago(30m)
| where Success == false
| take 20

If nothing comes back, widen the window to ago(1d). Demo data can be quiet.

Common Mistake

Forgetting the time filter. The query scans days of data, runs slowly, and mixes today's incident with last week's normal.

Lesson 3: Choosing and Computing Columns

Concept. project keeps only the columns you list, so results are readable. extend adds a new column, computed from others. Many of our custom fields live inside customDimensions. Pull one out with tostring(customDimensions["name"]).

KQL · LessonSlow Requests With Their Client Versionproject, extend, and a custom field
requests
| where timestamp > ago(1h)
| extend client = tostring(customDimensions["client.version"])
| extend seconds = duration / 1000
| project timestamp, name, seconds, resultCode, client
| top 10 by seconds desc

top 10 by seconds desc sorts and keeps the 10 largest. desc means biggest first.

Exercise 3. From AppRequests in the last day, show the 10 slowest requests with only these columns: time, name, duration in seconds, result code.
Answer
KQL · AnswerExercise 3
AppRequests
| where TimeGenerated > ago(1d)
| extend seconds = DurationMs / 1000
| project TimeGenerated, Name, seconds, ResultCode
| top 10 by seconds desc

Lesson 4: Counting and Grouping

Concept. summarize collapses many rows into a few numbers. by makes one result per group: per service, per result code, per feature. Application Insights may sample data, keeping 1 row to stand for several. The itemCount column says how many, so count with sum(itemCount) to get the true number.

KQL · LessonRequests and Failures per Servicesummarize with by, using itemCount
requests
| where timestamp > ago(1h)
| summarize total = sum(itemCount), failed = sumif(itemCount, success == false) by cloud_RoleName
| order by failed desc
FunctionGives you
count()Number of rows (wrong if the data is sampled)
sum(itemCount)The real number of events
sumif(itemCount, condition)The real number where the condition is true
dcount(column)The number of distinct values (for example, distinct users)
avg, max, minAverage, largest, and smallest. Don't use the average for latency (see Lesson 5).
Exercise 4. From AppRequests in the last day: for each result code, how many requests were there? Biggest first.
Answer
KQL · AnswerExercise 4
AppRequests
| where TimeGenerated > ago(1d)
| summarize requests = sum(ItemCount) by ResultCode
| order by requests desc
