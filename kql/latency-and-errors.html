Module 2: Latency & Errors

The two signals behind most of our incidents. After this module you can measure P50 and P95, calculate an error rate correctly, see when something started, compare it with yesterday, and tell which layer the time or the errors come from.

  • Latency: percentile(duration, 50) and percentile(duration, 95). Never avg.
  • Error rate: 100.0 * failed / total, with both counted using itemCount.
  • bin(timestamp, 5m) + render timechart shows when. Comparing with yesterday shows whether it's unusual.
  • The dependencies table shows calls to other layers: the model, partners, search.

Lesson 5: P50 and P95

Concept. P50 (the median) is the typical wait: half of requests are faster. P95 is the bad-day wait: 1 in 20 requests is slower. Averages hide slow requests, so we always use percentiles.

KQL · LessonP50 / P95 per Service, Last HourThe two numbers we always report
requests
| where timestamp > ago(1h)
| summarize p50_ms = percentile(duration, 50),
            p95_ms = percentile(duration, 95),
            requests = sum(itemCount)
    by cloud_RoleName
| order by p95_ms desc
Reading the Result

P50 normal but P95 high means a subset is slow (one region, instance, partner, or long prompts). Both high means something broad (capacity, a dependency, a deploy).

Answer

Lesson 6: Error Rate

Concept. The error rate is failed ÷ total × 100. Two traps: KQL does whole-number division if both sides are whole numbers, so write 100.0 to get decimals, and count with itemCount. Then look at which result codes are failing, because 401, 429, and 5xx mean very different things.

KQL · LessonError Rate per Service, With Failing CodesThe correct way to calculate a percentage
requests
| where timestamp > ago(1h)
| summarize total = sum(itemCount),
            failed = sumif(itemCount, success == false),
            failing_codes = make_set_if(resultCode, success == false)
    by cloud_RoleName
| extend error_pct = round(100.0 * failed / total, 2)
| order by error_pct desc

make_set_if lists the distinct failing codes, so you can see at a glance whether it's 401, 429, or 500. The primer explains what each one means.

Exercise 6. From AppRequests (last day), calculate the error rate per AppRoleName, to 2 decimals, highest first.
Answer
KQL · AnswerExercise 6
AppRequests
| where TimeGenerated > ago(1d)
| summarize total = sum(ItemCount), failed = sumif(ItemCount, Success == false) by AppRoleName
| extend error_pct = round(100.0 * failed / total, 2)
| order by error_pct desc
Common Mistake

failed / total * 100 with whole numbers gives 0. Start with 100.0 * so the maths uses decimals.

Lesson 7: Over Time, and Compared With Yesterday

Concept. bin(timestamp, 5m) groups rows into 5-minute buckets, and render timechart draws them. That shows when it started. To know if a number is unusual, compare it with the same hour yesterday.

KQL · LessonP95 Over Time for One ServiceWhen did it start? Getting better or worse?
requests
| where timestamp > ago(6h) and cloud_RoleName == "writing-assist-svc"
| summarize p50 = percentile(duration, 50), p95 = percentile(duration, 95) by bin(timestamp, 5m)
| render timechart
KQL · LessonNow vs the Same Hour YesterdayIs this normal?
requests
| where timestamp > ago(1h) or timestamp between (ago(25h) .. ago(24h))
| extend period = iff(timestamp > ago(1h), "now", "yesterday")
| summarize p95_ms = percentile(duration, 95),
            error_pct = round(100.0 * sumif(itemCount, success == false) / sum(itemCount), 2)
    by cloud_RoleName, period
| order by cloud_RoleName asc, period asc

Lesson 8: Dependencies and Layers

Concept. The dependencies table records calls from our services to other layers. The target column says where the call went: the AI model host, a partner API, the search service. This is how you locate the layer.

KQL · LessonWhich Downstream Layer Is Slow or Failing?P95 and failures by dependency target
dependencies
| where timestamp > ago(1h)
| summarize calls = sum(itemCount),
            p95_ms = percentile(duration, 95),
            failed = sumif(itemCount, success == false)
    by target, type
| extend fail_pct = round(100.0 * failed / calls, 2)
| order by p95_ms desc
