KQL Training

KQL (Kusto Query Language) is how we ask questions of our telemetry. Most of our services have no dashboard, so being able to write a few simple queries is what lets you see the problem yourself instead of waiting for someone else. This training starts from zero and builds up to the queries in our playbooks.

  • Three modules, 12 lessons: Basics, Latency & Errors, Across Layers. Each lesson takes 10–15 minutes.
  • Every lesson has a plain-English concept, a worked example, an exercise you can run for free, and an answer.
  • Finish with the quiz and cheat sheet.

Where to Practice

Log Analytics Demo Workspace

Free, real-looking application telemetry from Microsoft. Sign in with any Microsoft account, then open Azure portal → Log Analytics → Demo (search for "Log Analytics demo"). The exercises use its AppRequests, AppDependencies, and AppExceptions tables.

Our Application Insights

Once you have access: open the Nimbus Application Insights resource, then Logs. Our examples use these tables: requests, dependencies, exceptions.

Azure Data Explorer Help Cluster

For pure KQL practice: dataexplorer.azure.com, cluster help, database Samples (for example the StormEvents table). Good for learning the language itself.

How a Query Reads

A KQL query reads top to bottom, like a recipe. Start with a table, then each | (pipe) passes the rows to the next step.

KQL · LessonRead It Like a Sentence"From requests, keep the last hour, count them per service, biggest first."
requests                                   // 1. start with a table
| where timestamp > ago(1h)                // 2. keep only the last hour
| summarize total = sum(itemCount) by cloud_RoleName   // 3. count per service
| order by total desc                      // 4. biggest first
