RAG, Agents & Model Changes

Modern AI features rarely make one model call. They retrieve context, call tools, chain steps, and pass through safety filters. Each step adds latency and a new way to fail, and some of the worst regressions come from changes to prompts, data, or models rather than code.

  • RAG = search for relevant context, then send it to the model. Retrieval adds latency, and context adds tokens.
  • Agents chain several model and tool calls. Latency multiplies, and one slow tool slows the whole answer.
  • Evals are the AI equivalent of tests. Without them, prompt and model changes ship blind.
  • Content filters can block requests and look like errors.

Retrieval-Augmented Generation (RAG)

  1. EmbedThe question is turned into a vector (a numeric representation of meaning) by an embedding model, which is another model call.
  2. SearchA vector or hybrid search index finds the most relevant chunks of documents.
  3. AssembleThe chunks are added to the prompt as context.
  4. GenerateThe model answers using that context.

In Nimbus, the personal knowledge base is on the device, so much retrieval happens locally. Cloud retrieval is used for enterprise documents and web answers (via the research partner).

Agents and Tool Calls

An agent lets the model decide to call tools (search, calendar, partner APIs via the integration platform) and loops: think → call tool → read result → think again → answer. Every loop adds a model call and a tool call.

Latency Multiplies

Four steps of 1.5 seconds each is 6 seconds before any answer. A tool that occasionally takes 10 seconds puts that 10 seconds into the P95 of every feature that uses it.

  • Maximum steps per request, so a confused agent can't loop forever.
  • Timeouts per tool, shorter than the overall request budget.
  • Circuit breakers per partner tool, with a graceful answer when a tool is down.
  • Retries with backoff and a budget, not unlimited.
  • A trace for every step, so you can see which step was slow.
Ask: "How many model calls and tool calls does this feature make per request at P50 and P95? Which step is slowest?"

Model and Prompt Changes

These change behavior without a deploy, so they're often missing from "what changed?" lists:

  • A new model version (manual or automatic upgrade).
  • A system prompt or template edit, often stored in config or a feature flag.
  • New tools added to an agent.
  • Retrieval settings: chunk count, ranking, index rebuilds.
  • Routing policy between the device model and the cloud model.

Insist that they're logged in the change feed (AI change management).

Evals

An eval is a fixed set of example inputs, with a way to score the outputs for quality, safety, length, and format, run before a change ships. It's the AI equivalent of a test suite.

Weak

Someone tries a few prompts by hand before shipping.

Good

A versioned eval set runs for every prompt or model change, scoring quality and output length.

Best

Evals gate the release, latency and token counts are compared too, and production samples continually refresh the eval set.

Content Filters

Hosted models usually run safety filters on both input and output. A blocked prompt typically returns a 400 with a content-filter error. A blocked answer may come back as a normal response with a finish reason that marks it as filtered.

When Filters Look Like Outages

A prompt template change, or a new model version with different filter behavior, can cause a jump in 400s or empty answers. Ask: "What share of errors are content-filter results, and did that share change?"

Go Deeper
  • Semantic caching returns stored answers for similar questions. It cuts latency and cost, but carries a risk of stale or wrong answers.
  • Structured output (JSON mode, function schemas) reduces parsing failures in agent tool calls.
  • Small vs large models: routing simple tasks to smaller models improves latency and cost, and adds a routing decision to monitor.
